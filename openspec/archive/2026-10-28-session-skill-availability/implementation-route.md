## Boundary contract

The model-facing request contains only `{ snapshotId, components }`, with exact keys and bounded sizes. The host-resolved delegation contains the allowed component subset, derived operations/targets, original finding/evidence identities, task attempt and dependency state. A typed optional preparation field on the existing `deck_delegate` request is the smallest way to nominate snapshot/component IDs; it is validated against host state before becoming a durable delegation. The model does not author the resulting grant. No modifying authority comes from a readiness block, task prompt, prior report or an arbitrary `agent` field.

The service receives two separate inputs: that narrow request and a host-created invocation binding. The binding includes canonical project, session/epoch, task/attempt/launch, selected role/verified generation, actual requesting runner, delegation identity, current scope/policy and evidence. Where an optional initializer is needed, the host selects an eligible existing enabled binding; the caller cannot choose an executor or backend. The role binding and current turn must agree. Availability of a tool and configured member intent are not proof that the native invocation actually launched with that role.

Under a canonical project/target lock, recheck live caller/dependencies, source digest, current scope and enabled consumers immediately before reservation/effect. Resolve target and operation from the trusted catalog, reject report-only or indeterminate findings, then issue and consume one process-local reservation for the exact effect. Persist the intent/outcome and recheck the affected project evidence. A resumed attempt receives a fresh binding. A request admitted before cancellation must not mutate after its caller is revoked; recheck after asynchronous reads and immediately before effect. The same fencing applies after last-consumer disablement.

Credentials authenticate possession of a host-issued task grant under the existing local trust model. They are not OS isolation between mutually hostile processes running as the same user. Raw-client spoof acceptance means absent/invalid/revoked credentials or another role's credential cannot gain Setup authority; do not claim that a stolen valid Setup credential proves a different process identity.

Long-running optional initializers must not be forced through the bridge's current 15-second default timeout (`mcp-bridge.ts:18,97`). For this first bounded YAML effect, preserve that timeout and reconcile interrupted calls through the durable attempt record. Later initializers need a bounded operation/status contract within this same service, not silent retry or a global timeout increase.
