# Antigravity (`agy acp`) runner parity — MVP: agy as Lead

Design reference: `docs/agy-runner-parity.md` (Spanish, user-authored). Precedent: `openspec/changes/claude-runner-parity/brief.md` and the Claude runner modules in `crates/host/src/claude*.rs`.

## Intent

The user wants to use Google models in Deck as soon as possible. First MVP: select Antigravity (`agy`, runner id `agy`) as the **Lead** of a session, with model and thinking-level discovery and assignment, and with the Lead able to delegate through Deck's `deck_*` session MCP to the members on already-integrated runners (Codex, Claude Code, OpenCode).

## Acceptance (MVP)

1. Agents/assignment UI lists runner `agy` ("Antigravity") with models and per-model thinking levels discovered from the installed `agy acp`; the user can assign agy+model+level to the Lead and save.
2. A Lead turn on agy streams assistant text and activity (tool calls) into the chat, completes, and persists native session ownership; the next turn continues the same agy conversation via `session/resume`.
3. The agy Lead receives the Deck session MCP (`deck_delegate`, `deck_task_*`, `deck_decision_*`, ...) and successfully delegates a task to a member on an existing runner; the result continues the Lead through Deck's normal continuation path.
4. Permissions follow the same Deck policy as the Claude/Codex Leads (trusted project, ordinary workspace edits apply directly in writable sessions with YOLO on or off, escalations go to a Deck decision when YOLO is off; Deck's own MCP tools never prompt).
5. Stop/cancel works (`session/cancel` then process-group kill); after daemon restart an interrupted attempt is settled without automatic replay, and a queued message runs exactly once (AGENTS.md continuity rules).
6. Readiness: missing binary or unauthenticated agy yields an actionable unavailable reason, never a crash; no secrets or personal identifiers exposed.
7. Hermetic fake `agy acp` fixture covers the above in `cargo test -p deck2`; no live model requests in tests.

## Non-goals (MVP)

agy as a delegated member (`agy_member.rs`), external MCPs (CBM, Context7) for agy, image attachments, live steering, quota card, process reuse across turns, runner icon polish. These are later increments.

## Phase 0 protocol evidence (agy 1.5.16, live, Google AI Pro tier, 2026-11-25)

Captured with a scratch driver; raw logs are disposable under `target/agyspike/` (not committed).

- Launch: `agy acp --stdio` (flags: `--sandbox`, `--dangerously-skip-permissions`, `--process-per-session`, `--add-dir`, `--log-file`, `--disable-telemetry`). JSON-RPC 2.0 NDJSON on stdio.
- `initialize {protocolVersion:1, clientCapabilities:{fs:{readTextFile:false,writeTextFile:false},terminal:false}}` → capabilities as in the design doc; `authMethods` list. Auth state is not reported here; tier arrives in `session/new` `_meta.antigravity.tier` (`{name:"Google AI Pro", id:"g1-pro-tier"}`).
- `session/new {cwd, mcpServers:[{type:"http", name, url, headers:[{name:"Authorization", value:"Bearer …"}]}], _meta:{antigravity:{systemPrompt:{append:"…"}}}}` → `{sessionId, models:{availableModels:[{modelId:"gemini-4-neon-high", name}], currentModelId}, modes:{currentModeId:"default", availableModes:[default, accept-edits, auto, plan]}, configOptions:[model, thought_level, mode], _meta.antigravity.tier}`.
  - `configOptions.model.options[].value`: base model ids (`gemini-4-neon`, `gemini-4-carbon`, `gemini-4-argon`, `gemini-4-hydrogen`, `gemini-pro-orchestrator[-neon|-argon]`, `gemini-3.8-flash`, `claude-opus-5-5`, `claude-sonnet-5-5`, `gpt-oss-120b-medium`).
  - `configOptions.thought_level.options`: `low|medium|high|xhigh`. Valid levels per base model are the suffixes present in `availableModels[].modelId` (e.g. neon/hydrogen have xhigh, carbon/argon/flash only low/medium/high, orchestrators and gpt-oss have none).
  - Catalog mapping for Deck: `modelId` = base model value, `label` = option name, `thinkingLevels` = suffixes found for that base (empty when none).
- `session/set_config_option {sessionId, configId:"model"|"thought_level"|"mode", value}` → full `configOptions`; also emits `config_option_update`.
- `session/prompt {sessionId, prompt:[{type:"text",text}]}` → result `{stopReason:"end_turn"|"cancelled", usage:{inputTokens, outputTokens, cachedReadTokens, cachedWriteTokens, thoughtTokens, totalTokens}}`.
- `session/update` notifications (`params.update.sessionUpdate`): `agent_message_chunk {content:{type:"text",text}}`, `agent_thought_chunk`, `tool_call` / `tool_call_update {toolCallId, name, args, status: in_progress|pending|completed, kind: edit|other|…, title, locations, rawInput, rawOutput, content:[{type:"diff",path,newText}]}`, `usage_update {used, size}` (context window, size 1048576), `available_commands_update`, `config_option_update`, `session_info_update {title}`.
- MCP: the HTTP server with Authorization header works (agy sends `server/discover`, `initialize` protocol 2025-11-25, `tools/list`, `tools/call`). Tools appear to the model as `mcp_<server>_<tool>` (e.g. `mcp_deck_deck_ping`) and **also trigger `session/request_permission`** — Deck must auto-allow its own session MCP tools.
- `session/request_permission` is a server→client request with **string ids** (`"1"`): `{sessionId, toolCall:{…as tool_call…}, options:[{optionId:"allow",kind:"allow_once"},{optionId:"deny",kind:"reject_once"}]}`. Response: `{outcome:{outcome:"selected", optionId}}` (ACP also defines `{outcome:"cancelled"}`). No allow-always option is offered.
- Continuity: `session/resume {sessionId, cwd, mcpServers, _meta}` in a fresh process restores the conversation (model recalled earlier tool result). **The system prompt append persists in the stored session and accumulates on resume** — append role instructions on `session/new` only; do not re-append on resume.
- Cancel: notification `session/cancel {sessionId}` mid-turn → the pending `session/prompt` returns `stopReason:"cancelled"`; the session remains usable.
- No quota or steering extensions observed.

## Decisions

- Runner id `agy`, label "Antigravity"; `NativeRunner::Agy`, `NativeTransport::AgyAcp`.
- Pure Rust ACP client over the child's stdio, no Node bridge.
- One `agy acp` process per Lead turn in the MVP (reuse later); own process group, recorded native pid.
- Model inventory must not create a new agy conversation on every UI fetch: cache the discovered catalog (keyed by agy binary identity) and refresh on demand / expiry.
- Context window: map `usage_update {used,size}` to the existing context observation if cheap; otherwise leave it for the next increment.
