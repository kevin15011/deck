# Codex launch without Supermemory project identity

## Intent

Missing verified repository identity must disable Supermemory for this Codex launch rather than block the runner. Preserve saved preferences and real identity isolation; never invent a repository scope. No memory tokens, recall/flush effects or runtime host may become active in this fallback. Installed Deck memory hooks must be suppressed safely for the process without editing global registrations. Conflicts/corruption are not silently classified as missing identity.

## Implementation and evidence

The missing-identity fallback uses a cloned session config with memory disabled and the original selected config for content-only materialization. No provider preparation or global runtime-file rewrite occurs. `-c features.hooks=false` is prepended only to the child command; all hooks, including user/RTK hooks, are temporarily disabled to guarantee installed memory hooks remain inactive. The user explicitly accepted this session-only limitation. Saved configuration is preserved. Missing credentials for a valid identity, corrupt stores and normal verified-memory launch guards remain blocked rather than silently downgraded.
