# Web daemon restart working brief

## Authorized outcome
Menu-only Restart Deck secondary action on mobile and desktop, including standalone PWA. One confirmation dialog; force checkbox defaults off and describes interruption of work and resolution of pending approvals/questions. No chat/header clutter. Stable installation is primary; preserve current installation channel and custom prefix. No downloads or implicit upgrade/channel switch.

## Design direction
Architect task-3aae7f84-fdf3-498d-a1f9-03aa7d0273aa revision3 (result87545/ended87546) supersedes manifest-dependent revision2. Canonical install.sh and upgrade regular stable executable paths are supported without new manifest migration. Canary resolves validated alias to digest payload using existing installer directory semantics. Browser supplies no command/path/argv. Unsupported untrusted/dev installation shapes fail explicitly.

Use CLI-injected launcher/provenance capability; session-host must not import CLI. Capture launcher path at process startup; validate ownership/mode and channel before handoff. A detached helper establishes readiness while old daemon remains available. Private atomic durable pending intent becomes committed before accepted response/shutdown. Pending/aborted intents cannot launch. Preserve state roots, config, port, authentication and history. Reuse canonical shutdown/start behavior; do not implement stop-only restart.

Normal restart retains busy guard; restart request itself must not count as busy. Explicit force drains admission and records truthful forced interruption/denial/cancellation reasons. Authenticated device and existing Host/Origin/proxy checks apply; no isolation claim against same-user processes. No MCP or CLI force extension in this scope. Preflight binds current daemon, target and affected work; stale token refreshes same dialog. One restart slot and idempotent request identity.

## Lead constraints on implementation
Compare helper digest and channel to preflight BEFORE committed intent; ready response alone is insufficient. Revalidate stable target around launch to handle atomic upgrade races. Require exact spawned identity, changed nonce and expected executable digest before reporting success; nonce change alone is not success. Same/different build does not imply newer version. No path or credentials in browser output. Preserve recovery history and never infer task staleness from timeout. Source helpers must not create dependency cycles by sharing installer validators.
