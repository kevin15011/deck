## V2 design requirement: immediate session-local availability

Newly accepted captured memory MUST remain available to the appropriate agent within the current Deck session before remote Supermemory processing finishes. A bounded local session buffer is an implementation option, not a finalized architecture choice. The design must define isolation by session/project/sharing policy, eligibility/redaction before storage, bounded size and eviction, role injection budgets, chronological supersession, deduplication when remote memories become ready, acknowledgement/failure handling and session-close behavior. Local availability must not masquerade as confirmed durable remote storage or broaden sharing. Tests must show next-turn access while remote status is queued/dreaming, replacement/reconciliation after completion, and no cross-session/project leakage. Size, retention window and delivery targets will be justified using measured p50/p95 processing delay and realistic availability results; do not invent these limits before measurement. Include this requirement and the chosen approach in the Phase1 design/ADR work; no product implementation is authorized in this Phase0 harness delta.
