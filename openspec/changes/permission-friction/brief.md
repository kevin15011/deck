# Working Brief: permission-friction

## Intent
The user must not spend a session approving permissions. Reduce prompts to the minimum while keeping protected Git discard operations behind fresh informed confirmation.

## Observed defects (Lead trace, candidate 3eb07355)
1. Silent Bash denial. `crates/host/src/claude_bash.rs:46-49` returns None when `execution_view::bounded` alters the action (control chars such as newlines in heredocs or multi-line `-m`, >1024 chars, or substrings `password|secret|token=|token:|api_key|apikey|authorization|bearer |basic |sk-`). The bridge then denies with the generic `Deck did not authorize this tool call.` (`crates/host/bridge/claude.ts:275`). The user is never asked and the model gets no reason. `sk-` false-positives on ordinary words such as `task-`, `disk-`.
2. "Any" exists only for Claude Read/Grep/Glob (`crates/host/src/permission_bounds.rs:497-512`). Bash offers at most "This command, any timeout" (plain words only) or "Same command family" (9 families). `git -C <dir> <sub>` parses `-C` as subcommand and is never reusable.
3. Attention bubbles (`frontend/src/sidebar.tsx:31` useSidebarAttention, `frontend/src/sidebar-attention.tsx`) include the currently viewed session, duplicating the inline chat permission card.
4. Permission cards do not react immediately after a decision; they appear still clickable after accepting.

## Acceptance
- A1 Non-renderable Bash: the user is prompted with a faithful, reviewable rendering (escaped control chars / full text, no silent truncation) instead of a silent denial; if a request truly cannot be presented, the denial message states the concrete reason. Secret-looking values must still not be displayed in clear text; matching uses token boundaries so `task-`, `disk-` etc. are not flagged.
- A2 Session "Any" for Bash in the current project, plus an equivalent session-scoped "Any" for nearly every other permission kind (Claude tools, relays, Codex command/file/capability requests where the host can bound it to project/session). Grants are session-scoped and revoked with the session/project trust as existing grants are.
- A3 Exceptions never covered by any broad grant and always freshly confirmed: Git operations that discard or rewrite work (reset, restore, checkout -- / checkout with paths, clean, stash drop/clear, rebase, push --force, branch -D, etc.), `dangerouslyDisableSandbox`, background execution. Existing exact-only behavior stays for these.
- A4 `git -C <project-root or descendant> <sub> ...` is evaluated like `git <sub> ...` for reuse/families; other paths stay exact.
- A5 Attention bubbles exclude the session currently being viewed.
- A6 Accepting/denying a permission updates the card immediately (optimistic pending state, controls disabled), and duplicate clicks cannot submit twice; the final host state reconciles.

- A7 (added by user during attempt 1) Pending permissions for the Lead and its members float in a dock anchored above the composer, so chat scrolling cannot lose them. Cards are more compact. Visual agreement: keep the existing Deck palette, icons and density, avoid new styles, and do not shift the transcript layout. The dock stacks requests with a bounded height and scrolls internally. The command or summary stays on one line with an expandable full view. Options and allow/deny stay on one compact row. Keyboard access and focus are preserved, with focus moving to the next request after one is resolved. The dock appears only for the viewed session.

## Non-goals
Changing Codex sandbox policy, removing the protected-Git confirmation, redesigning the permission card visuals.
