# Claude parity: session skills and role safety blocks

Status: diagnosis in progress.

## Intent

User (2026-10-26): Deck skills are installed in each runner and must be reachable by agents in the cross-runner session (Lead and delegated members), available on demand through the runner's native skill mechanism, not injected into every prompt. Treated as a serious parity defect, separate from `test-strategy-and-suite-pruning`.

## Governing invariant (user, 2026-10-26)

Deck has one core that executes inside each native runner. The cross-runner session MUST run that same core and MUST NOT behave differently from Deck running natively in the same runner: same roles, same skills, same hooks, same execution plugins/policies, same safety blocks and the same native capabilities. The session-host may add only what is inherent to cross-runner operation (task ledger, `deck_delegate` delegation in place of native subagents, approval relay, cross-runner evidence), and every such difference must be explicit, minimal and justified. Any other divergence is a defect.

## Known evidence

- `sessionRolePrompt` (`apps/cli/src/session-service.ts:83-96`) injects only the role body; skills are left to native loaders (`apps/cli/src/session-shared-services.ts:57`).
- Claude session children receive `--plugin-dir` only for the ready memory plugin (`packages/adapter-claude/src/session-driver/launch.ts:62,110`); the native interactive launch passes the Deck team plugin (`packages/adapter-claude/src/runner-adapter.ts:~525`). A live Claude Lead session lists no Deck skills.
- Pi passes the Deck package via `--extension`; OpenCode adds `~/.claude/skills` and `~/.agents/skills`; Codex relies on native config. Not yet verified empirically.

## Second defect (Lead-verified, 2026-10-26)

`getAgentContent(id, {promptProfile: "legacy"})` omits both the `CRITICAL_SAFETY_GIT_DISCARD_PROTECTION` block and the Adaptive Developer Team Contract for all adaptive roles (lead, apply-fast, apply-deep, quality, investigate, architect); `compact` includes both. The installed native Claude plugin (`~/.local/share/deck/claude/developer-team-v2-5034c66b64acd19e/agents/*.md`, 7 agents) contains neither, and its hooks (`rtk-hook.cjs`) do not enforce git discard protection. Native Claude Deck agents therefore run without the mandatory git safety rule. Found by apply-fast `task-09d3d118-1f29-42bf-9f83-bb3d6603c18c`; verified by Lead.

## Acceptance

- In every runner, a session child (Lead and member) can discover and load every Deck skill installed for that runner, by the name role instructions use.
- No session-incompatible plugin parts (agents, hooks, native delegation) leak into session children.
- Parity check covers all four runners.
- Every adaptive role in every profile and runner carries the git discard protection block and the team contract; a structural guard fails if any materialized role lacks them.
